# Database migrations

KnowledgeDebt `0.x` uses Alembic for versioned schema upgrades. SQLite remains the zero-configuration development database; PostgreSQL 16 is the deployment target.

## Before upgrading

1. Stop writes to the backend.
2. Back up the relational database and resource storage together.
3. Install the new backend dependencies.
4. Run the migration against a restored copy first.
5. Start the application only after `alembic upgrade head` succeeds.

```bash
make backend-install
make migrate
```

Compose runs the same migration command before Uvicorn starts.

## Existing SQLite installations

If `KNOWLEDGEDEBT_DATABASE_URL` is empty, Alembic's default URL targets the local data database. Confirm that the path in `backend/alembic.ini` and `KNOWLEDGEDEBT_DATA_DIR` refer to the installation you intend to upgrade.

The baseline migration is idempotent for current tables and explicitly adds the recording-range, storage, transcript-global-time, and adaptive-question columns used by earlier SQLite prototypes. It also converts legacy per-media Course Profile weights to the four evidence channels. An application startup compatibility migration remains in place during `0.x` for old local databases, but new schema changes should always be expressed as Alembic revisions.

## PostgreSQL

Set the URL for the migration process:

```bash
export KNOWLEDGEDEBT_DATABASE_URL='postgresql://user:password@host:5432/knowledgedebt'
cd backend
../.venv/bin/alembic -c alembic.ini upgrade head
```

The URL is normalized to the psycopg 3 SQLAlchemy dialect. CI starts PostgreSQL 16, applies every migration, and runs a core repository flow against it.

## Creating a revision

Update SQLAlchemy metadata in `backend/app/orm.py`, then create and review a revision:

```bash
cd backend
../.venv/bin/alembic -c alembic.ini revision --autogenerate -m "describe the change"
../.venv/bin/alembic -c alembic.ini upgrade head
```

Autogenerated migrations are a draft, not proof. Review defaults, nullability, indexes, backfills, downgrade behavior, SQLite compatibility, and data volume. Add a migration test before opening a pull request.
